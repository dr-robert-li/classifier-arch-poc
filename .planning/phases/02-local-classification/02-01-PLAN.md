<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gateway → Ollama (guard) | Untrusted model output crosses back into the gateway and is parsed |
| user prompt/response text → DLP scanner | Untrusted, possibly secret-bearing text is scanned and partially hashed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | parse_guard_output | mitigate | Parser returns ("unknown",[]) on any non-conforming guard output; never trusts model text to drive control flow |
| T-02-02 | Information Disclosure | dlp_scanner matched_value | mitigate | Store only sha256(matched_text) in matched_value; never store/log the raw secret (Pitfall 4) |
| T-02-03 | Denial of Service | dlp_scanner regexes | mitigate | All patterns length-bounded/anchored; entropy + Luhn are O(n); no unbounded backtracking (ReDoS) |
| T-02-04 | Spoofing | guard prompt-injection | accept | Guard runs in its own isolated /api/chat call with only conversation messages; it never receives gateway control instructions, so a "talk the guard into safe" prompt cannot alter scanner or gateway decisions |
| T-02-05 | Information Disclosure | guard adapter logs | mitigate | Adapter logs only status/exception text, never raw prompt/response content |
| T-02-SC | Tampering | npm/pip installs | accept | No new packages introduced (research Package Legitimacy Audit: stdlib re/math/hashlib + existing httpx only) |
</threat_model>
