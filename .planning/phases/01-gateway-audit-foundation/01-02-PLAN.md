<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chat client retry → gateway | A retrying client supplies conversation_id + message_id; the gateway must not let a crafted/replayed pair duplicate or corrupt audit events |
| gateway → Ollama (failure) | Unavailability must fail safe (audited 503), not crash or leak a stack trace |
| events reader → SQLite | Read path must not interfere with the append-only writer (WAL concurrent read) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering / Repudiation | Audit completeness under failure | mitigate | `prompt.received` persisted before the Ollama call; a `system.error` event is written on failure so an attempt can never go unaudited (REL-03, SC-5). |
| T-01-07 | Tampering | Duplicate/replayed event injection | mitigate | UUID5 event_id keyed on (conversation_id, message_id, event_type) + `INSERT OR IGNORE` rowcount gate makes replays no-ops; turn_index derived from completed responses keeps the key stable across retry (AUDIT-04, SC-4). |
| T-01-08 | Denial of Service | Ollama down / slow | mitigate | ConnectError/Timeout/404 mapped to a clean HTTP 503 with `audited: true`; httpx timeout bounded by `ollama_timeout_seconds`; gateway never hangs unbounded or 500s. |
| T-01-09 | Information Disclosure | system.error event content | mitigate | system.error stores only the prompt SHA-256 and a fixed `[error — content not generated]` preview, not raw generated content (none exists); files remain 0o600. |
| T-01-10 | Tampering | /events read connection | accept | Read-only query over a separate WAL connection; no write path exposed. Read-only by construction; no parameter allows mutation. |
</threat_model>
